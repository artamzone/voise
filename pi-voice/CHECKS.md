# Фактические локальные проверки Pi Voice

Первичная проверка: 6 октября 2026 года на этой машине. Системные компоненты, драйвер, настройки микрофона и системный PATH не изменялись. Тестовые процессы завершены; уже запущенный пользователем экземпляр Pi Voice необходимо перезапустить после изменения исходников.

## Текущая отправка Shift+Insert через SendInput

Ручная проверка предыдущего варианта выявила: `keyboard.press/release` не вставляет текст в pi.dev, но clipboard обновлён и ручной Shift+Insert работает. Для этой версии заменён только механизм отправки в `src/pi_voice/windows.py`; распознавание, CUDA, модель, микрофон и алгоритм clipboard не изменены.

- Win32-механизм: `ctypes.WinDLL("user32", use_last_error=True).SendInput` с полным `INPUT` union (40 байт на x64), `KEYEVENTF_SCANCODE` и `KEYEVENTF_EXTENDEDKEY` для основной Insert.
- События: левая Shift DOWN (0x2A), основная Insert DOWN (E0 0x52), Insert UP, Shift UP. Один DOWN Insert; повторов при ошибке/частичной отправке нет.
- До отправки F8 проверяется через hook и Windows; после отпускания — пауза 50 мс и повторная проверка. Фокус не меняется. Оба UP вызываются через вложенный `finally`; результат каждого SendInput проверяется, ошибки Windows/UIPI выводятся в консоль.
- Добавлены диагностические сообщения `Recognized: ...`, `Clipboard updated`, `F8 released`, `Sending Shift+Insert via SendInput`, `Paste sent`. Консоль теперь содержит распознанный текст; файловые логи не создаются.
- Проверен код установленного `keyboard`: единственный подавляющий hook Pi Voice зарегистрирован для F8; Shift/Insert проходят. Старый путь использовал `keybd_event` без extended-флага для Insert. Новая отправка независима от `keyboard.send/press/release` и его флага `is_replaying`.
- **32 unittest — OK**, `compileall` с `-W error` — код 0, `pip check` и `git diff --check` — OK.
- **Реальный `local_smoke.py` — код 0**: два цикла F8, активный подавляющий F8 hook, четыре ожидаемых события Shift/Insert наблюдены, однократная вставка русского clipboard в тестовое окно, клавиши отпущены, Enter не отправлен. Временный WAV удалён.
- Автоматически подтверждена вставка в тестовое окно Windows. После перехода на SendInput пользователь также подтвердил успешную реальную работу в pi.dev: «все ок». Системные права/настройки не менялись.

## Предыдущая попытка через keyboard.press/release

Пользователь подтвердил вручную: распознавание и вставка в Telegram работают; в pi.dev Ctrl+V вставляет clipboard дважды, а Shift+Insert — один раз, включая русский Unicode.

- Вставка изменена только в `src/pi_voice/windows.py`: Shift DOWN → Insert DOWN → Insert UP → Shift UP; одна отправка, без Enter и посимвольного ввода.
- Clipboard и его опциональное восстановление не изменены. До вставки проверяются отпускание F8 (глобальный hook и Windows), Insert и модификаторов; при удержании более секунды текст остаётся в clipboard без автоматической вставки.
- Отпускание Insert/Shift выполняется в `finally`, включая ошибку отправки.
- Faster-whisper, CUDA, модель, микрофонный код и зависимости не изменены.
- После исправления **27 unittest — OK**, `compileall` с `-W error` — код 0, `pip check` — OK.
- Дополнительный `local_smoke.py` остановился до клавиатурной вставки: Windows отказала в `SetForegroundWindow` для тестового окна. GPU-распознавание синтетической фразы прошло; успешная Windows-вставка новой версии этим запуском не подтверждена.
- Для ручной проверки перезапустите `.\pi-voice\start.cmd --offline`, дождитесь Ready, продиктуйте две фразы в pi.dev через F8. Проверьте однократную вставку, отсутствие Enter и отсутствие удерживаемых Shift/Insert.

Остальные результаты ниже относятся к первичной версии с Ctrl+V. Текущие результаты SendInput приведены в первом разделе.

## Окружение и зависимости

- Интерпретатор внутри `.venv`: **Python 3.13.4, Windows x64** (проверен `sys.version`; первичный вывод `python --version` был противоречивым).
- NVIDIA GeForce **RTX 3080 Ti**, 12288 MiB, драйвер **595.97**.
- `nvidia-smi`: поддержка драйвером CUDA **13.2**. Системный CUDA Toolkit не обнаружен; для работы не потребовался.
- В `.venv` установлены: faster-whisper **1.2.1**, CTranslate2 **4.8.2**, PyAV **16.1.0**, NumPy **2.5.3**, sounddevice **0.5.6**, keyboard **0.13.5**, pywin32 **312**.
- Проектные NVIDIA DLL: cuBLAS **12.9.2.10**, cuDNN **9.27.0.42**, транзитивный NVRTC **12.9.86**. DLL загружаются только для процесса утилиты.
- Все 32 установленных пакета с версиями записаны в `requirements.lock.txt`; `pip check` прошёл.
- Первый скачиваемый пакет оборвался сетевой ошибкой; повторная установка завершилась успешно.
- PyAV 19.0.1 оказался несовместим с вызовом `metadata_errors` в faster-whisper 1.2.1. Зафиксирован PyAV 16.1.0; реальное декодирование WAV покрыто регрессионным тестом.

## Модель и замеры

**large-v3-turbo**, язык **ru**, GPU 0, **cuda / float16**. Модель скачана в `models/`; `model.bin` около 1543 MiB. Алиас Hugging Face перенаправлен на `dropbox-dash/faster-whisper-large-v3-turbo`, revision `0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf`.

CTranslate2 обнаружил один CUDA GPU; фактический объект модели сообщил `device=cuda`, `compute_type=float16`. Выполнен реальный инференс, а не только проверка наличия GPU. Первый GPU-прогрев: **0.338 с**.

Тестовая фраза создана **локальным Windows SAPI, Microsoft Irina Desktop — Russian**:

> Посмотри текущий проект и проверь, почему не работает тёмная тема.

Распознано:

> Посмотри текущий проект и проверь, почему не работает тёмная тема

Длина синтетического аудио: **6.098 с**. Последний успешный прогон: **0.213 / 0.169 / 0.166 с**, среднее **0.183 с**. Замер включает локальное распознавание/VAD/сбор текста, но не загрузку модели, длительность записи и обработку Ctrl+V целевой программой. Это не замер голоса пользователя через микрофон; время зависит от фразы и нагрузки GPU.

## Что нужно проверить вручную

1. Запустите из `C:\Users\user\voise`: `.\pi-voice\start.cmd --offline`.
2. Дождитесь **Ready**, переключитесь в **pi.dev**. Проверьте, что Shift+Insert разрешён в настройках вашего терминала.
3. Удерживайте **физическую F8**, произнесите тестовую фразу обычным голосом, отпустите F8.
4. Убедитесь, что текст вставился в позицию курсора, **Enter не нажат и команда не отправлена**.
5. Дождитесь Ready и повторите. Не меняйте поле/окно до завершения вставки.
6. Проверьте приложение Windows, в котором хотите использовать диктовку, с тем же уровнем прав.

Автоматически подтверждены программные Win32 F8 и вставка в тестовое окно, но **не физическая клавиша, качество вашего голоса через микрофон и настройки pi.dev/других целевых приложений**. Восстановление сложных clipboard-форматов не реализовано; обычный текст восстанавливается только при явном `--restore-clipboard`, без гарантии времени чтения целевым приложением.
